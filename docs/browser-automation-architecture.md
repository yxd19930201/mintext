# 浏览器自动化最终架构

## 通道职责

- **经济、标准模式**：继续使用用户配置的 API 模型。
- **免费模式主通道**：统一由青玉浏览器助手领取 `browser_ai` 任务，在用户已登录的 DeepSeek 或 ChatGPT 网页执行。
- **免费模式兼容通道**：只有浏览器助手离线时，才使用桌面内置的旧网页适配器。
- **平台发布**：番茄章节发布、覆盖和状态回传同样由青玉浏览器助手执行。

## 统一任务链路

1. 业务功能只调用统一 `AIService`，不直接操作网页或判断 API Key。
2. `AIService` 根据生成模式选择 API 或免费网页通道。
3. 免费网页通道检测浏览器助手在线状态；在线则创建具备幂等键的 `browser_ai` 任务。
4. 浏览器助手领取任务，在目标网页执行并持续续租、回传进度。
5. 后端等待结构化结果，并将结果交还原业务服务写入大纲、正文、短剧、分镜或体检报告的对应位置。
6. 登录失效、验证码、扩展更新或浏览器中断时，任务保留；用户处理后可按同一幂等键恢复。

## 可靠性约束

- 同一幂等键不会并发重复提交，避免网页重复生成。
- 运行任务租约过期后可被重新领取，避免浏览器或扩展异常退出造成永久卡死。
- `waiting_user`、失败及旧版本任务在用户重试后可重新排队。
- 扩展每 2 秒尝试领取新任务，并用 Chrome Alarm 作为后台休眠后的兜底。
- 网页执行结果只有在后端确认保存后才清理对应网页会话。
- 浏览器助手离线才切换旧网页适配器，不允许同一任务同时由两条通道执行。

## 功能覆盖

所有实际调用 AI 的功能都经统一服务选择通道，包括小说大纲与正文、连续性审核与返修、账本提取、小说转短剧、短剧剧本、分镜脚本以及 AI 助手完整体检。保存、删除、导出、同步和人工编辑等本地操作不创建 AI 任务。
