# 定稿后的摘要、记忆与下一批

生命周期服从 `lifecycle.md`。本文件只处理 canonical 之后的正史记忆。

## 执行顺序

1. 审核登记为 `pass`。
2. 运行 `finalize`，把独立草稿提升到 `chapters/`。
3. 读取最终章节，而不是审核前草稿。
4. 完成 `memory/deltas/` 中本批记忆差异单，更新 `02-章节滑动摘要.md` 与 `memory/伏笔与钩子账本.md`。
5. 运行 `sync-memory`；成功后才可创建下一批并重写 `03-当前批次任务.md`。
6. 需要发布时再入队。

未进入 `chapters/` 的内容不得写入 `02` 为既成事实。
差异单必须引用本批 canonical 指纹；正文变更后，旧差异单与同步状态立即失效。

## 单章摘要

每章记录：

- 章节功能；
- 主要因果；
- 谁做了什么选择；
- 人物状态变化；
- 新增或改变的设定；
- 爽点收益与代价；
- 伏笔新增、延续、回收；
- 下一章承接。

摘要写事实，不写文学渲染。

## 批次摘要

每个批次必须记录：

- 小故事：诱因、推进、局部结算、余波；
- 大主线交付：更近、更远或改变方向；
- 主角处境、信息、资源、关系、名声和风险的变化；
- 反派真实收益和威胁升级；
- 谁知道什么，谁仍不知道；
- 伤势、债务、承诺、契约和道具归属；
- 最近爽点类型和下一批冷却；
- 下一批直接冲突。

批次结尾至少有一项不可逆变化。

## 当前状态区

`02` 顶部必须能让新 Agent 不读旧正文也能继续：

- 当前章节和篇章；
- 时间、地点和直接冲突；
- 大主线位置；
- 主角和主要人物状态；
- 能力、资源、伤势、债务和秘密；
- 当前盟友、敌人和摇摆者；
- 未解决伏笔及最后出现章；
- 下一步动作。

## 20章轮回

每四个默认五章批次生成轮回摘要：

- 四个小故事概览；
- 大主线推进；
- 高潮和失败；
- 人物与关系变化；
- 力量、资源和地位变化；
- 新增设定与人物；
- 已回收和未回收伏笔；
- 爽点分布和重复风险；
- 下一轮目标。

更早内容只保留轮回摘要；最近20章保留较详细摘要。

## 知识状态

秘密必须记录四项：

```text
事实：
知道者：
误解者：
证据：
```

这比只记录“发生了什么”更重要，可防止角色无故知道答案。
