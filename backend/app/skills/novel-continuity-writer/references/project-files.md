## 权威层级

项目文件分四层，不能互相替代：

1. `01-全局设定与创作规则.md`：作品宪法。只放冻结后的长期承诺、硬规则、全书目标和分卷总览。
2. `design/`：战略设计层。根级五份总控管理人物、争斗、亲密、文风和因果；每卷使用唯一的 `design/卷NN-卷名/`，其中 `README.md` 管卷级总纲，`章XX-XX.md` 管3—5章逐章细纲。
3. `02-章节滑动摘要.md`：正史事实层。只记录已定稿正文造成的人物、信息、资源、伏笔和关系变化。
4. `memory/`：高精度且可追溯的正史记忆层；账本保存线索详情，差异单记录批次变化，卷级摘要保存长期归档。
5. `03-当前批次任务.md`：战术执行层。只驱动当前3到5章批次。

`design/` 可以比 `01` 更详细，但不得与 `01` 冲突；如果设计决策改变了全书目标、硬规则、结局方向或分卷结构，必须同步修订 `01`。

## 四个核心文档

### `01-全局设定与创作规则.md`

只保存长期稳定事实和全书总控：

- 题材、子类型、目标读者、目标字数、预计卷数和总体读感；
- 一句话卖点、读者承诺和每10章/每卷必须兑现的爽感；
- 主角终极目标、核心缺陷、底线、成长终点和结局方向；
- 全书核心矛盾、最大敌对力量、终局形态；
- 分卷总览：每卷章节范围、阶段功能、主角变化、敌人层级和卷末不可逆变化；
- 世界、力量、旅行、复活等硬规则；
- 人物目标、秘密、口吻和关系动态；
- 势力与反派阶梯；
- 分卷里程碑、伏笔上限和爽点冷却；
- 内容安全边界。

逐章事件不要写入 `01`。只有正史改变全局规则时才更新。

### `design/`

保存长篇设计过程和卷级细案。初始化时创建：

- `design/01-人物志.md`：人物欲望、底线、口吻、关系节拍、反派资源和败亡条件。
- `design/02-争斗时间线.md`：战争主骨、卷级日历、敌人阶梯、不可逆得失、债务与证据速查。
- `design/03-情感与同房设计.md`：成年自愿关系、亲密事件、利益后果、主动方与动作轮换。
- `design/04-文风与禁区.md`：项目语言、能力话术、标题、亲密文风、章尾钩子与禁写项。
- `design/05-钩子与因果账本.md`：每3—5章读者承诺、结算、下一批发动机和长线设计ID。
- `design/卷NN-卷名/README.md`：本卷唯一总纲。
- `design/卷NN-卷名/章XX-XX.md`：逐章完整梗概，每章固定包含`冲突、推进、香、钩`四栏；“香”专指有实际动作、双关、距离、同意、风险与主线后果的擦边，普通信任或利益变化不能代替。

禁止同时维护`卷一/`与`卷01-卷名/`两套卷级目录。格式、标题和同步门禁详见`design-system.md`。卷级细纲不是正文；正文仍然只能进入`drafts/`和`chapters/`。

### `02-章节滑动摘要.md`

只保存已定稿正史：

- 当前章节、篇章、地点、时间、直接冲突；
- 当前人物状态、伤势、资源、债务、承诺和知识状态；
- 最近20章详细摘要与更早轮回摘要；
- 伏笔最后出现章、当前线索和建议回收区间；
- 最近爽点类型与冷却；
- 下一批直接承接点。

### `03-当前批次任务.md`

只驱动当前未完成批次：

- 起止章节和生命周期；
- 大主线交付；
- 小故事诱因、阻力、局部结算、余波；
- 每章功能和结尾钩子；
- 人物与关系变化；
- 爽点轮换；
- 必须推进、禁止事项、审核门槛。

审核结论放 `reviews/`，不要长期堆入 `03`。批次定稿后，重写 `03` 为下一批任务。

### `memory/`

- `伏笔与钩子账本.md`：唯一保存 `F-`、`H-` 详情、物证与知识差。
- `deltas/`：每批 canonical 的记忆差异单，必须带 canonical 指纹。
- `delta-index.json`：差异单、`02`、账本的哈希索引；用于恢复与失效判断。
- `卷级正史摘要/`：已结束卷的压缩正史；不默认注入写作上下文。

详细规则见 `memory-model.md`。

### `04-发布流水线与状态.md`

人类可读发布摘要：

- 登录状态；
- 最新 canonical、queued、processed、verified 章节；
- 当前待发布范围；
- 最近运行结果和错误；
- 是否存在“因平台限制保留 queued、下次再发”的章节。

机器状态以 `publishing/ledger.json` 为准。

## 初始化

```powershell
python <skill>/scripts/novel_workflow.py --project <目录> init --title "书名" --genre "题材" --volumes 4
```

命令会创建四个核心文档、`design/` 战略设计目录、创作状态、发布状态、目录和三个项目工具。

初始化不是直接开写。必须先与用户做总体目标访谈，至少确认：

- 题材与子类型；
- 目标平台、目标读者和目标读感；
- 目标字数、预计章节数、预计卷数；
- 主角终极目标、初始处境、核心缺陷和成长终点；
- 全书核心矛盾、最大敌对力量和结局方向；
- 第一卷必须解决的问题；
- 每10章稳定兑现的爽点；
- 不能写偏的内容边界。

访谈的稳定结果写入`01`；展开内容写入design根级五份总控、`design/卷01-卷名/README.md`和首批`章01-05.md`。首批细纲每章必须有完整梗概及`冲突、推进、香、钩`四栏，其中香专指真实擦边机制。只有这些信息足以支撑第一批时，才创建首批：

```powershell
python tools/novel_workflow.py mark-designed
python tools/novel_workflow.py start-batch --from-chapter 1 --to-chapter 5
```

## 旧项目迁移

- `03-当前写作任务与审核.md`：读取后拆分。当前任务进入新 `03`，历史审核结论移入 `reviews/`。
- 批次合并草稿：下次返修时拆成独立章节 `.txt`；已定稿章节不强制改名。
- 缺少 `workflow/state.json`：根据 `chapters/` 最大连续章号初始化 `latest_canonical_chapter`。
- 旧发布运行时：执行 `python tools/novel_publish.py migrate`。
- 若旧项目只有真实登录态，迁移的是项目自己的 `.runtime/fanqie/state.json`；不要把真实登录态抄进 skill。

迁移时先保留旧文件，验证新状态后再删除重复文件。
