# 长篇小说 Design 设计系统

本文件定义 `design/` 的唯一标准格式。`design/` 保存尚未发生的战略设计，不是正史；正文是否发生只以 `chapters/`、`02` 和记忆账本为准。

## 目录

1. 标准目录
2. 根级五份总控
3. 卷级 README
4. 五章逐章细纲
5. 标题体系
6. 设计与批次同步
7. 修改边界与验收

## 一、标准目录

```text
design/
  01-人物志.md
  02-争斗时间线.md
  03-情感与同房设计.md
  04-文风与禁区.md
  05-钩子与因果账本.md
  卷01-卷名/
    README.md
    章01-05.md
    章06-10.md
    章11-15.md
    章16-20.md
  卷02-卷名/
    README.md
    章21-25.md
    ...
```

- 每卷只保留一个目录，使用 `卷NN-卷名`。禁止再建并行的 `卷一/00-本卷总纲.md` 等重复目录。
- 根级不再创建 `00-初始化访谈`、`00-总纲`、`01-全书路线图` 等与 `01` 或五份总控重复的文件。
- 初始化访谈形成的稳定承诺写入 `01-全局设定与创作规则.md`；展开信息进入本文件规定的五份总控和卷级 README。
- 常规每卷20章、每五章一份细纲；项目另有卷长时仍以3—5章为一个小故事文件，不跨卷混放。

## 二、根级五份总控

### `01-人物志.md`

保存主角、核心关系人物、盟友、反派和长期配角：

- 身份、年龄、外形锚、口吻；
- 欲望、底线、秘密、独立利益；
- 战场功能与不可工具化边界；
- 分卷关系节拍；
- 反派资源、合理优势和败亡条件。

不保存逐章流水，不把未定稿行为写成正史。

### `02-争斗时间线.md`

保存全书主骨：

- 主要战争/事件编号、所在卷、胜负标志和专属手段；
- 对手强度、资源来源、为何不能立即碾压主角；
- 卷级日历、旅行、伤势与程序时长；
- 每卷不可逆得到与失去；
- 冲突类型轮换、贯穿反派收支；
- 债务、物证和权力来源速查。

### `03-情感与同房设计.md`

保存成年人关系设计：

- 人物各自欲望、边界、主动方式和关系阶段；
- 暧昧/亲密事件编号、所在章区间、触发、关系收益与事后代价；
- 修罗场的利益冲突与明确结果；
- 接触载体、主动方、空间、第三人和打断方式轮换。

所有角色必须成年、清醒、自愿、能够拒绝。亲密不能凭空生成股权、执法权、医疗权限或政治投降；正文表现继续服从 `satisfying-structure.md` 和项目 `01`。

### `04-文风与禁区.md`

保存项目专属表达规则：

- 目标读感、视角、语言、称呼和地位话术；
- 爽点公式、能力话术、证据后台如何翻译成人话；
- 亲密文风、标题规则、章尾钩子强弱对照；
- 绝对禁写、AI腔搜索词和单章交稿检查。

### `05-钩子与因果账本.md`

保存未来设计的因果网络：

- 每3—5章读者承诺、本批结算、下一批发动机；
- 长线钩子设计 ID、首次窗口、新信息、最晚回收；
- 能力边界、权力取得和证据持有设计；
- 每卷钩子与终局回收。

它是设计账本，不替代 `memory/伏笔与钩子账本.md`。只有 canonical 后，已经发生的事实才进入 memory。

## 三、卷级 `README.md`

每卷目录的 `README.md` 是本卷唯一总纲，至少包含：

```markdown
# 卷X｜卷标题（章节范围）

| 项 | 内容 |
|---|---|
| 命题 / 主爽 | |
| 舞台 | |
| 主敌与有效资源 | |
| 不可逆失 | |
| 不可逆得 | |
| 主角位置变化 | |
| 核心关系线 | |
| 能力升级与代价 | |
| 贯穿反派收支 | |
| 卷末发动机 | |

## 对手资源与反制证据
## 核心债务、物证与权力来源
## 本卷验收
```

卷标题必须能概括本卷独特动作、物件、位置或结果，避免“危机、风波、崛起、较量”等空词。卷名修改时同步根级五份总控和 `01` 的分卷总览，但不借改名改变剧情。

## 四、五章逐章细纲

文件名使用实际范围，如 `章01-05.md`、`章96-100.md`。标准结构：

```markdown
# 卷X · 第 1–5 章（逐章梗概）

> 本批主爽/读者承诺：
> 本批不用能力也赢/关系变化/主要代价：

---

## 第1章　标题

用完整段落写清：开章压力、人物为何同场、主角主动选择、对手有效阻力、关键动作、公开反馈、收益、代价和章末发动机。

- **冲突：**
- **推进：**
- **香：**
- **钩：**
```

要求：

- 一章只承担一个主要可复述事件，但必须改变信息、关系、资源、风险或位置；
- 梗概要写证据来源、持有人、权力让渡和人物知识边界，不能只写气氛词；
- **先写结果，再决定载体**：细纲优先锁定“谁承认了什么、哪条线进入何种程序、主角得到什么可用结果”，不要默认把结果死绑为“必须签某份确认书/必须交某个U盘”。只有该具体载体本身承担不可替代的翻盘、知识差、代价或钩子时，才把它列为字面硬兑现；否则允许正文用更可信、更自然且权限合法的等价载体兑现。
- 细纲冻结前做一次“合同内冲突审计”：逐项检查指定动作/证物是否与自愿、程序可信度、人物权限、既有正史和文风自然度冲突。若“必须打一巴掌”与“随后在店内自愿签认”等要求会互相削弱，必须在动笔前重写合同，不能把矛盾留给正文靠补丁解决。
- **控制证据复杂度**：一个证据尽量只用一个主载体完成一个剧情功能；能沿用原机、原账、原监控就不要再派生U盘、截图、打印件、会议本和只读副本。新增一个可移动证据物，细纲必须同时写清`谁生成/取得、谁有权操作、当前持有人、是否有副本、何时交还或移交、下一窗口`；写不清就删物件或合并载体。
- 每五章在动笔前列出“证据与权限预算”。原则上只保留推动翻盘、知识差或下一批钩子所必需的载体；同一事实若出现三个以上介质，必须说明各自不可替代的剧情作用，否则合并。不要用增加程序名词冒充严谨，程序细节必须带来可见收益、代价或风险。
- `香`专指擦边，不是普通关系变化、并肩做事、护短或利益同盟。每章必须落下实际暧昧动作、双关、身体距离或临界互动；写清正事承载、双方欲望、谁主动、谁回应、谁能叫停、第三人/危险、临界停止及主线收益；
- 只有“她担心他、两人并肩、她替他作证、关系更信任”而没有实际擦边动作，判定为假香，必须重做；
- 章末写具名对象已经开始的动作、期限、危险或选择，不写“更大危机即将来临”；
- 五章形成一个小故事，并把后果推给下一份细纲。

## 五、标题体系

标题必须先于正文确定，但只能承诺章内真实发生的内容。

- 4—16个汉字，短、硬、具体；
- 指向本章独有的人物、动作、物件、关系、危险或利益；
- 默认每五章至少两个标题具备正常解释与暧昧解释，其余在爽、险、秘密、证据、利益之间轮换；
- 不连续复用“她、腿、亲、湿”等刺激词，不连续复用同一句式骨架；
- 标题变更必须同步细纲标题、README索引、`03` 和草稿文件名/首行；正文已 canonical 时必须走正史复审，不能只改文件名。

标题的双义、兑现和评分服从 `satisfying-structure.md` 与 `reviewer-rules.md`。

## 六、设计与批次同步

权威流向：

```text
01长期承诺
→ design根级五份总控
→ 当前卷README
→ 当前五章细纲
→ 03写前合同
→ drafts
→ 审核与canonical
→ 02和memory
```

- 规划新批前必须读取根级五份总控、当前卷 README 和对应五章细纲；不得要求写稿 Agent 读取全部120章设计。
- `03` 只提取当前批可执行信息，不复制整卷细纲。
- 正文与设计冲突时：已定稿事实以 canonical 为准；设计 Agent 修正未来细纲，不反向篡改正史。
- 改总体剧情时先改根级总控，再改卷 README、相关五章细纲和 `01`；只改标题时不得顺手改事件、人物命运、物证或结局。

## 七、修改边界与验收

设计修改完成后检查：

- 章号从1到目标章连续、无重复、无遗漏；
- 每卷只有一个 `卷NN-卷名` 目录；
- 每章标题在 README、细纲、`03` 和现有草稿中一致；
- 每五章有读者承诺、局部结算、不可逆变化和下一批发动机；
- 人物年龄、关系进度、伤势、债务、能力、证据与权力来源无冲突；
- 每章`香`栏都有可写成现场的真实擦边机制，不以普通信任/利益变化冒充；
- 擦边设计没有替代同意或主线收益；
- 未把未来设计写入 `02` 或 memory 为既成事实。

任一项不成立，design 不能标记完成，也不能进入写稿阶段。
