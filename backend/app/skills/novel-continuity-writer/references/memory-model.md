# 分层记忆模型

## 文件职责

- `02-章节滑动摘要.md`：当前可写状态；保持固定七段结构。
- `memory/伏笔与钩子账本.md`：唯一保存 `F-`、`H-` 的详细条目、物证与知识差。
- `memory/deltas/`：每个 canonical 批次一份记忆差异单，记录“什么变了、依据是什么”。
- `memory/delta-index.json`：轻量索引与哈希；不承载故事内容。
- `memory/卷级正史摘要/`：卷结束后的长期正史压缩。

同一事实只在权威位置完整保存一次；`01`、`02`、`03` 只引用线索 ID。

## `02` 固定结构

1. 当前快照：章节、时间地点、直接冲突、大主线位置。
2. 当前有效状态：人物权力、资源、伤势、债务、关系和知识差。
3. 活跃钩子与伏笔索引：只写 ID 与一句状态。
4. 最近五章单章摘要。
5. 第 6—20 章按每五章一条批次摘要。
6. 历史卷级索引：每卷三至六条不可逆结论和归档路径。
7. 爽点冷却与下一批直接承接。

## 线索账本

- 长线伏笔使用 `F-001`，短期钩子使用 `H-001`；ID 永不复用。
- 每条至少记录：首次出现章、读者已知、真实作用、知道者、误解者、证据与持有者、最后推进章、下次推进窗口、最晚回收、写作限制、状态。
- 未回收线索、物证持有、知识差、未结债务和仍约束剧情的承诺不得被压缩掉。

## 差异单与压缩

- `finalize` 依据最终 `chapters/` 创建本批差异单，并写入 canonical 指纹。
- 只在差异单、`02` 和账本完成回写后运行 `sync-memory`。
- 差异单只记录本批新增、改变、关闭的事实；不复制全量人物表或旧章节摘要。
- 最近批次保留完整差异单；历史批次只通过 `delta-index.json` 按需追溯。
- 超过二十章时合并旧批次摘要；卷结束时写入卷级正史摘要，旧差异单归档且不默认注入上下文。

## 失效规则

若已定稿章节被正史复审后改变，原差异单和索引指纹失效；必须重新审核、重新定稿并重新同步记忆。聊天记录、废稿和未通过审核内容永远不是记忆来源。
